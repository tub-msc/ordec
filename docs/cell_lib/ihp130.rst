:mod:`ordec.lib.ihp130` --- IHP SG13G2 technology
=================================================

This cell library provides part of the `IHP Open PDK <https://github.com/IHP-GmbH/IHP-Open-PDK>`_.

.. _ihp130_substrate_lvs:

Substrate handling in LVS
-------------------------

All SG13G2 resistors (``Rsil``, ``Rppd``, ``Rhigh``) have a third pin ``bn`` connecting the device's bulk/substrate node. In LVS netlists, the resistors are emitted as three-terminal SPICE elements, so substrate connectivity is part of the layout vs. schematic comparison.

On the layout side, the SG13G2 LVS deck merges the resistors' bulk into a single chip-wide substrate (pwell) net. For hierarchical designs, this has the following consequences:

* The net a resistor's ``bn`` is wired to in the schematic must be the net the layout's substrate is tied to, in every cell of the hierarchy.
* In the normal case no extra port is needed: wire ``bn`` to the net of the substrate tap (usually ``vss``) and place a ``Ptap`` on that net inside the cell that owns the resistor.
* If the substrate net is not one of the cell's ports, the cell needs a substrate port. Every cell whose layout contains a resistor (directly or in a subcell) is extracted with an *additional, implicit pin* for the propagated substrate net (even though the cell's layout draws no substrate pin shape), and its schematic then needs a matching substrate port (named ``sub`` by convention) wired to the ``bn`` pins of all resistors and propagated down the hierarchy. Within the hierarchy, KLayout matches the extracted substrate pin against this port *topologically*. Subcell layouts need neither a pin shape nor a label for it.
* The *top* cell is the exception: top-level pins are compared by name, so the top layout must materialize the substrate connection explicitly. Place a substrate tap (``Ptap``) and attach a labeled Metal1 pin to it (see cell ``C_Hier`` in ``tests/lib/lvs_example_hier.ord`` for a working example).

Approaches that do **not** work:

* A pin label directly on the substrate region: the deck's connectivity setup attaches no text/pin layer to the substrate, so such labels are ignored and the top-level substrate pin remains unnamed.
* Netlisting ``bn`` as a global net (``.global sub!``) instead of explicit ``sub`` ports: the subcells then match, but the top-level pin comparison fails because the layout's implicit substrate pin has no name to match against ``SUB!``.

Displayed device values
-----------------------

Schematic instances of the resistors and of ``Cmim`` show their nominal value
(``R≈`` and ``C≈``) next to the raw parameters. It is derived from the drawn
geometry with the typical-corner constants of the ngspice models
(``resistors_mod.lib``, ``cornerRES.lib``, ``cornerCAP.lib``):

.. code-block:: none

    R = rsh * leff / weff + 2 * rz / w
    weff = w + dw
    leff = (b + 1) * l + (2 / 1.85 * weff + ps) * b

with rsh = 7 / 260 / 1360 Ω/sq, dw = +0.01 / +0.006 / −0.04 µm and
rz = 4.5 / 35 / 80 Ω·µm for ``Rsil`` / ``Rppd`` / ``Rhigh``, and

.. code-block:: none

    C = 1.5 fF/µm² * l * w + 40 aF/µm * 2 * (l + w)

for ``Cmim``. The value is rounded to three significant digits and marked
with ``≈`` because secondary model effects are not included: straight
resistors match the simulated typical-corner value within about 1 %,
meanders within about 10 %. The labels are display-only and do not affect
netlists or simulation.
